## Phase 2.10 覆盖层渲染四连修（覆盖互压 / 均码变小 / 裁切 / 白底漏盖）

### 用户反馈（4 个相互纠缠的症状）
1. **选区之间互相覆盖** — 同一页相邻白底矩形互相侵入；
2. **白底无法覆盖所有原文** — 边缘仍有英文露出；
3. **均码变小** — 原本标题/正文字号差异巨大，翻译后所有译文大小一致且偏小；
4. **文字被裁切** — 部分行被白底裁掉、看不到完整译文。

### 根因（视觉证据：output/repro_rough_render.png + output/real_paper_seg5_close.png）
1. **`_cluster_columns` 的 overflow 段双重处理** —— 段既在原列又在 overflow 列 → 第二次以全宽 bg 画一次，盖掉邻列/原文。这是覆盖与「白底漏盖」的根本原因。
2. **col_bounds 用 25/75 分位裁剪** —— 在横跨坏段存在时拉偏分位数，列边界比段实际宽度窄 → 本列段被裁窄（文字被裁切）+ 段边缘漏在 clip 外（白底漏盖）。
3. **`p.drawText` 之前没有 `p.setFont(font)`** —— **核心 bug**：painter 默认 9pt 字体渲染所有译文，与 QTextLayout（用 CJK 字体计算行高+分行）的 chunk 完全不匹配 → 全部译文均码变小。
4. **`_fit_font_px` 被移除后没有字号适配** —— 长译文超过 `next_y -` 段就被 max_bottom 截掉。

### 修复
- **`src/ui/pdf/text_overlay.py`**：
  - **删除 `_cluster_columns` / `_fit_font_px` / `_measure_text_h`** —— 全部不再被调用。
  - **新增 `_compute_next_y(segs, page_h, origin) → dict[id, float]`**：以「x 范围是否重叠」判定每段的下方扩展上界（2px 缓冲）。不再做列聚类，根除 overflow 双重处理与分位裁剪问题。
  - **重写 `_render_page_pixmap`**：
    - 每段 clip 用自身 content_rect（不再用列分位）—— 白底/文字完整覆盖本段、不会盖到不重叠的他段；
    - 按 (y, x) 升序绘制，绘制顺序稳定；
    - 字号自适应循环：先按 base_px 排版 → 若 text_h > avail_h 则按比例 (0.9/0.8/0.7/0.65/0.6) 缩小，floor = `_COVER_MIN_FONT_PX`；
    - **关键**：每行译文 `p.drawText` 前必须 `p.setFont(font)`；
    - 改为 `AlignVCenter`（原 AlignTop）—— CJK × 0.85 比原文字号略小，顶对齐会让行底留白，垂直居中更像原版排版。
  - **`_COVER_PAD` 1.0 → 2.0** —— 覆盖原文抗锯齿边缘。
- **`scripts/repro_brown_layout.py`** —— 移除对 `_cluster_columns` 的直接调用，改用 `_compute_next_y`。

### 验证
- `output/real_paper_page0.png`：标题"对维拉与西蒙的回应"明显大于正文"认知科学 17"（字号差异化恢复）；白底完整覆盖；无段间互压。
- `output/brown_page0.png`：跨栏标题"短译文段 0"59px + 作者"短译文段 1"77px 还原；下方三栏正文独立白底、零跨列覆盖。
- `output/brown_page1.png`：标准三栏布局，每栏独立白底，译文在各列内正常换行填充。
- py_compile 通过；无残留引用。

## Phase 2.11 行间碰撞消除（行与行互相遮盖）

### 用户反馈
"每一段译文中每一行字都会挤压遮盖上一行字，行之间会互相遮盖"。
（_render_page_pixmap 的段间互压在 Phase 2.10 已修；这是段内行间的垂直互压。）

### 根因
- `_layout_flow` 主循环 `draw_rects.append((_lx, _ly, lw, max(_lh, line.height() * _LINE_LEADING)))` —— 行 Y 坐标 = 原文行 top，但行高 = `max(原行 bbox 高度, 译文行高)`。
- 译文字体（微软雅黑 CJK）`line.height() × 1.18` 通常大于原文行 bbox 高度（PyMuPDF 给的紧密 bbox）。
- 原文行 top 间距往往 < 译文行高 → 第二行译文顶（= 原文行 top）会顶进第一行译文底 → 文字矩形重叠 → 字互相遮盖。
- 剩余行循环 `extra_y = last_ly + last_lh`（用原文行高做增量）若译文行高 > last_lh，同样顶进上一行。
- fallback 原文行回退直接画在 `line_rects[i]` 原位置，译文行高若大于原文行间距，同样被译文行盖住。

### 修复
- **`src/ui/pdf/text_overlay.py`**：
  - 新增常量 `_LINE_GAP = 3.0`（行间最小垂直间距，像素）。
  - **`_layout_flow` 行间碰撞消除**：用 `cursor_y` 单调递增游标：
    - 首行 `cursor_y = line_rects[0][1]`（对齐原文首行 top）；
    - 每行 `ly = max(原文行 top, cursor_y)`，`cursor_y = ly + lh + _LINE_GAP`；
    - 剩余行从 `cursor_y` 累加（取代 `extra_y`）；
    - fallback（无 line_rects）分支同样 `y += hh + _LINE_GAP`。
  - **fallback 原文行回退碰撞消除**：从译文最后一行底 + _LINE_GAP 起作 `fb_cursor`，每行 `ly = max(原行 top, fb_cursor)`，`fb_cursor = ly + lh + _LINE_GAP`。
  - 设计权衡：原文行距充足时译文行仍贴合原文行（保持版式贴合）；原文行距不足时译文行自动向下推开，宁可缩小字号（已有自适应循环）也不允许行重叠。
- 新增 `scripts/repro_line_collision.py`：3 个针对性场景验证（紧密行距多行原文、1行原文→多行译文、字号自适应），3/3 通过。

### 验证
- `scripts/repro_line_collision.py` —— 三个场景相邻行 gap ≥ _LINE_GAP (3.0px)，零重叠。
- `output/real_paper_page0.png` 放大（`output/real_paper_page0_body_zoom.png`）：长译文段 seg[5] 折成 5 行清晰分行，行间距均匀。
- `output/brown_page1.png`：三栏正文段译文/回退行各自垂直有序，无任何行间遮盖。
- py_compile 通过。

## Phase 2.12 双栏 mode 独立 + 暂停后续传 + 混入英文归因

### 用户反馈（3 个）
1. **译文混入英文**：译文块里出现英文字（字体与译文大小一致），划词复制却不含这些英文 → 分析归因。
2. **暂停后无法重启**：单栏→双栏切换时翻译被暂停；之后点「译文/原文」切换按钮不再重启翻译，永远卡住。
3. **双栏左右都显示译文**：单栏切双栏后左右两栏都是译文；切回原文后变「左译文右原文」（设计应左原文右译文，切换只影响右栏）。

### 根因
- **问题 2**：`_on_rough_toggled`（src/ui/windows/main_window.py）checked 分支：
  `if viewer.has_rough_translations() or viewer.rough_is_running(): 复用呈现` —— 布局切换 cancel 后
  session 里有部分译文 → has_rough_translations()=True → 只 `set_cover_mode(COVER_TRANSLATED)` 复用，
  **不续传未译段** → 翻译永久停在暂停态。
- **问题 3**：`session["mode"]` 存视图模式；dual_viewer 左右栏 `load_pdf` 命中**同一 session dict**，
  `_activate_session` 里 `self._cover_mode = session["mode"]` → 左右栏都恢复为 translated；
  `set_cover_mode` 又写回共享 session["mode"] → 左右互相污染；dual 的 set_cover_mode 只作用右栏，
  左栏不再被同步 → 「左译文右原文」。
- **问题 1**：混入英文 = **未译原文行回退**（`_render_page_pixmap` 译文比原文短时，用 `seg.line_texts`
  剩余原文行在白底下补绘，Phase 2.9 用户要求"未译行不能留空白"）。绘制字号 base_px（原文），
  因 CJK ×0.85 视觉补偿与中文译文视觉等高 → 用户觉得"大小一致"。划词复制（selection.py 译文态）
  收集 `seg.display_text`（纯译文）→ 不含回退原文行 → "所见 ≠ 所得"。

### 修复
- **`src/ui/pdf/viewer.py`**（问题 3）：
  - session dict 删除 `"mode"` 字段；
  - `_activate_session`：`self._cover_mode = session["mode"]` → `COVER_TRANSPARENT`（视图模式是
    视图状态而非文档数据，不随 session 共享；激活会话一律原文态，由 UI 按钮决定）；
  - `set_cover_mode`：删除写回 `self._session["mode"]`。
  - 双栏左栏天然 transparent、右栏独立受控；布局切换重建 viewer 后回到原文态，点按钮进入译文。
- **`src/ui/windows/main_window.py`**（问题 2）：
  - `_on_rough_toggled` checked 分支重写：
    - `rough_is_running()` → 仅呈现（后台继续累积，不打断）；
    - 否则一律 `viewer.start_rough_translation(...)` —— 内部自动分派：全部已译→复用不重译 /
      部分已译→续传剩余段 / 无译文→全量启动。暂停后点按钮即恢复翻译。
- **问题 1**：仅归因（设计行为），未改行为。可选改进方向：①译文态复制拼入回退原文行（所见即所得）；
  ②去掉回退（违背 Phase 2.9 "未译行不留空白"需求）。待用户定夺。

## Phase 2.15 修 QPointF import + 字号自适应设计反思

### 用户反馈（运行时报错 + 设计批判）
1. **运行时报错**：`QPointF not defined` at `viewer.py:710` —— `cover_segment_at` 用了 `QPointF(cpos)` 但只 import 了 `QPoint`。
2. **设计批判**：当前字号自适应一遇到 text_h > avail_h 就缩字号，但"译文一般比原文简洁，空间都是足够的"。算法倾向计算横向空间，**忽略了纵向也有空间可以利用**——可通过"重新分段"（收窄行宽 → 更多行填充纵向）来放大字号，而非第一时间压缩字体大小。

### 修复
**1. QPointF import** — `src/ui/pdf/viewer.py` 第 18 行 `from PySide6.QtCore import ...` 加 `QPointF`。

**2. 字号 × 行宽 二维自适应（v1：含收窄填充）**
`src/ui/pdf/text_overlay.py` `_render_page_pixmap` 自适应分支重写：
- 先试 base_px + 原文行宽 → text_h ≤ avail_h → 用（默认）；
- text_h > avail_h → 缩字号（档位 + 下限 _FIT_MIN_FONT_PX=9 + 兜底）；
- **elif `text_h < avail_h × 0.75`（纵向富余大）** → 收窄行宽 ×0.8 重排，**仅当行数确实增加且仍在 avail_h 内**才采用；字号保持 base_px（不压缩）。

**3. v1 发现新 bug：数字截断**
真实渲染（`repro_real_paper.py`）暴露：seg[0] "认知科学 17, 495-499（1993）" 在收窄填充触发后，**数字 "1993" 被强行拆成 "(1" + "993"**——WrapAnywhere 在不合理位置（数字中间）断行，破坏可读性。0.8 行宽对短段 + 含数字/英文/标点的混合文本尤其危险。

**4. 收手（v2）：去掉收窄填充分支**
填充分支在含数字/英文/标点的混合文本上不稳定，**目前先去掉**，保留核心改进：
- **字号优先**：base 字号 + 原文行宽 → 放得下就用 base，**不第一时间压缩字号**（满足用户核心诉求）；
- 长译文放不下 → 才缩字号（档位 1.0/0.9/0.8/0.7/0.65/0.6，下限 9px）；
- 兜底：全部档放不下 → 强制 9px，宁轻微溢出/裁切。
- 「纵向富余时收窄行宽填充」作为后续可选优化，**需结合智能断行（词边界/标点优先）再启用**，避免数字截断这类问题。

## Phase 2.16 智能断行 + 横向碰撞（数字截断根因修复）

### 用户反馈（两个深度批判）
1. **数字截断的根因不是"收窄换行"**：而是 `_layout_flow` 用**原文行宽**作为行宽上限 —— 右侧明明没有碰撞段/没到页边时，译文仍被"自限换行"。这是 `_layout_flow` 的设计错误（用原文行宽 ≠ 用可用空间）。
2. **"收窄对混合文本危险"论点不成立**：处理的是译文（纯中文为主），智能断行（中文任意断、数字/英文按词不拆）即可解决。

### 根因（更深一层）
- `_layout_flow` 用 `WrapAnywhere`（任意处断）→ 数字 "495-499" 被硬拆成 "495-49" + "9..."；
- 行宽 = 原文行宽 `lw`（每行 setLineWidth(lw)）→ 即便右侧有大量可用空间，译文仍按 lw 折行 → 数字所在行被窄宽挤断。
- `_compute_next_y`（纵向碰撞）已有，但缺 `_compute_next_x`（横向碰撞）—— 行宽不受碰撞约束 = 自限。

### 修复
**1. 智能断行（`_layout_flow`）**：`WrapAnywhere` → `WordWrap`（Qt 默认）。Qt WordWrap 对中文任意字符间断行（每个 CJK 字符间有软换行点），对拉丁词/数字按词不拆（在空格/标点断，词内不拆除非超宽）。

**2. 行宽 = 横向碰撞可用宽度**：
- `text_overlay.py` 新增 `_compute_next_x(segs, page_w, origin) → dict[id, float]`：
  对每段找「右侧 + y 重叠」的最近段，左边缘即横向边界；右侧无碰撞段 → 边界 = page_w。返回页面局部 x（已扣 _SEG_GAP）。
- `_layout_flow` 增加 `line_width: float | None = None` 参数：传入时每行统一用 `line_width`（横向碰撞宽度），否则退化为原文行宽 lw（兼容旧调用）。
- `_render_page_pixmap` 调用 `_compute_next_x`，`avail_w = next_x - 段左 - GAP`，传给 `_layout_flow(line_width=avail_w)`。

**3. clip + 段级白底扩展**：行宽已是碰撞可用宽度，clip 必须同步放开（否则译文被裁回段宽）。
- clip 横向 = `[r.x-pad, next_x + pad]`；
- 段级白底宽度扩展到 `next_x - r.x`（盖住原文 + 右侧可用空白），视觉上「撑满」可用列宽（沉浸式风格）。

### 验证

  - A 智能断行：WordWrap 200px 下 "495-499（1993）" → 行 1 '495-499（1993）' 完整不拆 ✓
  - B 单行段（页眉，右侧无碰撞）：`next_x = page_w - GAP = 591`（行宽扩展到页边）✓
  - C 三栏 y 重叠：`next_x = 邻栏左 - GAP`（266/464），最右栏 = `page_w - GAP`（591）✓
- 真实渲染：`repro_real_paper.py` 数字 "1993" 单行完整保留 ✓；`repro_brown_layout.py` 三栏段白底撑满列宽、零跨列覆盖 ✓
- 全部回归通过：`repro_line_collision` 3/3、`repro_dual_mode` 全通、`repro_seg_drag` 全通、`repro_fit_adaptive` 全通、`repro_h_break` 全通
- py_compile 全过

### 收益
- 数字 "1993" 等混合内容**不再被硬拆**（智能断行 ✓）；
- 行宽**不被原文行宽自限**，译文可撑满可用列宽（横向碰撞 ✓）；
- 段级白底**撑满横向可用空间**，视觉饱满；
- 长译文行数减少（少换行 → 字号保持 base 不缩）；
- 全文碰撞体系完成**纵向（next_y）+ 横向（next_x）双轴**闭环。

## Phase 2.17 译文行 X 统一（"第二行奇怪缩进"修复）

### 用户反馈
"有些段落在第二行会出现奇怪缩进，表现为第一行和第二行不是同一个起点开始，第二行左侧会有大量空白，第三行部分会继承这种缩进。"

### 根因
`_layout_flow` 每行译文 X = 对应原文行的 `_lx`（**逐行贴合原文行**）。当原文段落存在：
- **首行缩进**（如学术段落首行空两格）：原文行 1 lx=50、行 2 lx=20 → 译文行 1 x=50（缩进）、行 2 x=20（顶格）→ 用户看到译文"首行缩进第二行突然顶格"。
- **悬挂缩进**（参考文献、列表项）：原文行 1 lx=20（顶格）、行 2 lx=100（缩进）→ 译文行 1 x=20、行 2 x=100 → **"第二行左侧大量空白"**，且剩余行继承 last_lx（最后一行 x）→ 缩进传播。

### 修复（`_layout_flow` 新增 `base_x` 参数）
- 传入 `base_x` → 所有译文行（含剩余行）统一从 `base_x` 起排（左对齐整齐）；
- 否则（None）→ 退化为跟随原文行 x（旧行为，兼容调用方）。
- `_render_page_pixmap` 三处调用传 `base_x = r.x()`（段左边界 = content_rect.x = 段内最小 lx）。

### 验证

  - 悬挂缩进原文（行 1 x=50、行 2/3 x=100）：
    - 旧行为：译文行 x = [50, 100]（第 2 行缩进 50px → 用户看到的 bug）
    - 新行为：译文行 x = [50, 50]（统一段左，整齐左对齐）✓
  - N0 旧行为存在参差缩进（场景有效）✓ / N1 新行为所有行 x=50 统一 ✓ / N2 text_h 不退化 ✓ / N3 无一行偏离段左 ✓
- 真实渲染：`repro_real_paper.py` 标题"对维拉与西蒙的回应"左对齐整齐（之前段内多行参差缩进消失）✓；`repro_brown_layout.py` 三栏正文段左对齐整齐 ✓
- 全部回归通过：`repro_line_collision` 3/3、`repro_dual_mode` 全通、`repro_seg_drag` 全通、`repro_fit_adaptive` 全通、`repro_h_break` 全通、`repro_indent_fix` 全通
